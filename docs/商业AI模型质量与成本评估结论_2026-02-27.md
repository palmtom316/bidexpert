# 商业 AI 模型质量与成本评估结论（归档）

- 归档日期：2026-02-27
- 来源：会话结论整理归档
- 主题：如何评价
  - 商业 AI 处理历史投标文件/规范/公司业绩/公司资质/管理人资质及业绩后入专家库的质量
  - 商业 AI 生成投标文件的质量
  - 以及如何据此进行模型与价格选择

## 1. 专家库入库质量评估现状

### 已有能力
- 已覆盖结构化类别：
  - `STANDARD`
  - `COMPANY_PERFORMANCE`
  - `COMPANY_QUALIFICATION`
  - `PM_QUALIFICATION_PERFORMANCE`
  - 见：`app/services/expert_library.py` 中 `_STRUCTURED_CATEGORY_MAP`
- 文档入库有完整流水：
  - 结构增强
  - 风险复核
  - 异常队列
  - 分块
  - KB 入库状态跟踪（`KBIngestRun`）
- EvidenceChunk 具备质量与治理字段：
  - `quality_score`
  - `valid_to`
  - `forbidden_tags`

### 关键缺口
- 结构化入库（你关心的公司业绩/资质/人员业绩等）当前分块质量分存在固定值：
  - `quality_score=88.0`
  - 这会导致模型之间质量差异无法真实反映到指标中
- `knowledge_quality.py` 的动态评分函数存在，但当前未接入主要入库路径，仅有测试覆盖

## 2. 投标文件生成质量评估现状

### 已有能力
- 生成三道闸：
  - 证据绑定
  - 证据句匹配
  - 覆盖率/强制条款校验
- 管线内有多重质量阻断与转人工：
  - 废标项覆盖不足
  - Global Facts 冲突
  - 证据临期
  - 审查拒绝
- 全文审查输出质量信号：
  - `coverage_estimate`
  - `score_estimate`
  - `modeled_issues`
  - `risk_points`
- 红线引擎有硬门禁：
  - 存在 `P0` => `BLOCKED`
  - 存在 `P1` => `NEED_FIX`
- 评分卡流程为“解析 + 人审确认后锁定”

### 注意事项
- `review_triage.py` 有清晰分层规则（PASS/REVIEW/REWRITE），但主流程中尚未形成强闭环接入，当前主要体现在测试中

## 3. 模型与价格选择能力现状

### 当前能做什么
- 可按角色/环境配置主备模型链（registry + fallback）
- 可按章节关键性路由（critical section）
- 可做运行时 fallback
- 可记录调用日志（tokens、fallback、latency、blocked）
- 可估算成本（基于模型单价与 token）

### 当前不能做什么（核心）
- 目前不是“按质量与价格自动最优选模”
- RL 路由优化目标是成功率 + 时延，不含直接成本目标
- 成本估算主要用于统计展示，不直接参与在线选模决策

## 4. 建议的可执行评价与选型框架

### 指标
- `IQ`（Ingestion Quality，入库质量）
  - 由：chunk 置信度、异常率、过期率、人审抽检通过率等组成
- `GQ`（Generation Quality，生成质量）
  - 由：三道闸通过率、coverage、redline 通过率、人审通过率组成
- `C`（Cost，成本）
  - 由：`LLMCallLog` token + pricing 单价计算“每份可交付稿成本”

### 选型公式（建议）
- `Utility = 质量分 / 成本`
- 或 `Utility = 质量分 - λ * 成本`

### 落地顺序
1. 先去掉结构化入库硬编码 `88.0`
2. 接入 `knowledge_quality.py` 到实际入库打分
3. 周期性统计每模型 `IQ/GQ/C`
4. 按 Utility 调整 registry 主备顺序
