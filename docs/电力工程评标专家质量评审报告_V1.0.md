# BidExpert 电力工程投标文件质量评审报告

> **评审视角：** 电力工程评标专家（注册一级建造师-机电/电力、高级工程师）
> **评审标准：** 《电力建设工程施工招标投标管理办法》、国家电网/南方电网招投标管理规定、GB/T 50326工程项目管理规范
> **达标要求：** 各模块达标率 >= 95%
> **评审日期：** 2026-02-24
> **评审版本：** release/V1.0
> **评审依据：** 源代码实际探查 + 投标实战经验

## 第一部分：总体评价

### 1.1 评审结论

**总体评分：58/100 — 不满足电力工程投标文件质量要求**

以电力工程评标专家实际评标经验衡量，本系统生成的投标文件存在**3项致命缺陷**（可直接导致废标）和**6项严重缺陷**（将严重影响评分），暂不具备独立生成可直接提交的电力工程投标文件的能力。

### 1.2 致命缺陷摘要（可导致废标）

| 序号 | 缺陷 | 影响 |
|------|------|------|
| F1 | 废标条款识别不完整，缺少电力行业专项废标条件 | 生成文件可能触发废标 |
| F2 | 章节生成Prompt缺少电力工程专业约束 | 施工方案、安全方案等内容不符合行业规范 |
| F3 | 全局事实提取缺少电力行业关键字段 | 关键参数（电压等级、输电距离、变电容量等）可能不一致 |

### M1 招标文件解析模块（达标率：72%）

**源文件：** `app/extract/tender_parser.py`, `app/services/tender_analysis.py`

#### 达标项（+72分）
- [x] 支持LLM+正则双通道解析（LLM优先，正则兜底）
- [x] 能识别强制性条款关键词（必须、应当、不得、须、必须满足）
- [x] 能识别废标/否决关键词（废标、否决投标、不予通过、取消投标资格等）
- [x] 能提取评分项及分值（SCORE_PATTERN）
- [x] 支持页码定位和章节锚点追踪
- [x] 五类关键信息分类（BIDDING_POINTS/SCORING_POINTS/COMPLIANCE_REQUIREMENTS/BONUS_POINTS/RISK_ALERTS）
- [x] 去重机制（_dedupe按category+content去重）

#### 不达标项（-28分）

**1. 缺少电力行业特有招标条款识别（-10分）**

电力工程招标文件具有行业特殊性，当前解析器缺少以下电力行业专项识别：

```
缺失的电力行业关键词：
- 电压等级要求（如"110kV及以上"作为资质门槛）
- 调试/送电/带电作业要求
- 继电保护配置要求
- 电力安全工器具要求
- 电力设施保护区施工要求
- 特种作业人员证书要求（电工证、高空作业证、焊工证）
- 电力建设工程质量监督要求
- 并网验收条件
```

**2. LLM解析Prompt缺乏电力行业引导（-8分）**

`tender_parser.py:27-31` 的 `_PROMPT_DESCRIPTION` 为通用描述，无电力行业专项指引：
```python
_PROMPT_DESCRIPTION = (
    "你是招标规则拆解引擎。"
    "任务：抽取 mandatory_requirements、scoring_items、deliverables。"
    ...
)
```

应增加电力行业专项解析指引（电压等级、调试要求、继保配置等）。

**3. 条款强度分级不够精细（-5分）**

当前仅分为 `MUST` / `GENERAL` 两级，电力工程招标通常需要至少四级：
- **废标级**（不响应直接废标）
- **否决级**（资格审查不通过）
- **扣分级**（影响评分但不废标）
- **建议级**（优先考虑/加分项）

**4. 缺少条款关联性分析（-5分）**

电力工程招标文件中条款常互相引用（如"详见第X章第Y条"），当前解析器无法建立条款间的引用关系。

### M2 废标条款识别模块（达标率：45%）

**源文件：** `app/extract/tender_parser.py:16-19`, `app/services/tender_analysis.py:40`

#### 达标项（+45分）
- [x] 基础废标关键词列表存在（废标、否决投标等8个）
- [x] 风险告警分类（RISK_ALERTS）已实现
- [x] 招标分析中包含 `_RISK_PATTERN` 正则

#### 不达标项（-55分）

**1. 电力行业专项废标条件严重缺失（-20分，致命）**

电力工程常见废标条件至少包括以下30+项，当前仅覆盖8个通用关键词：

```
严重缺失的电力行业废标条件：
A. 资质类：
   - 未提供电力工程施工总承包资质证书
   - 资质等级不满足招标要求
   - 安全生产许可证过期或无效
   - 项目经理无有效注册建造师证书
   - 项目经理同时在建工程超限

B. 技术类：
   - 施工组织设计未包含关键工序（如"杆塔基础施工""架线施工"）
   - 未提供调试方案或调试方案不完整
   - 施工工期超过招标文件规定
   - 未按规定格式编制施工进度计划（横道图/网络图）

C. 商务类：
   - 投标报价超过最高限价/标底上浮比例
   - 投标保证金未按时到账
   - 未按要求提供投标函原件
   - 法定代表人授权委托书缺失

D. 安全类：
   - 未提供安全生产许可证
   - 近三年有安全生产事故记录
   - HSE管理体系认证缺失（电力工程特别要求）

E. 格式类：
   - 未按招标文件格式要求装订
   - 电子标与纸质标不一致
   - 投标文件未加盖公章/未签字
```

**2. 废标条件未与章节生成联动（-15分，致命）**

当前废标条款识别仅在 `tender_analysis.py` 的分析阶段使用，但在 `generation_pipeline.py` 的章节生成阶段，**完全没有废标条款的检查逻辑**。生成的投标文件无法自动验证是否满足所有废标条件。

**3. 缺少废标风险等级评估（-10分）**

未实现废标风险评分机制。应对每个废标条件赋予风险权重，并在最终输出中给出废标风险总评分。

**4. 无废标条款追踪矩阵（-10分）**

缺少"废标条款 -> 投标文件响应位置"的追踪矩阵，评标时无法快速验证每个废标条件是否已被响应。

### M5 RAG检索与证据召回模块（达标率：70%）

**源文件：** `app/rag/rag_flow.py`, `app/services/qdrant_store.py`

#### 达标项（+70分）
- [x] 需求分解机制（decompose_requirement）

- [x] 多子需求并行检索
- [x] 证据合并与去重（merge_retrieval）
- [x] 覆盖率映射（coverage_map）
- [x] 证据过期预警机制（_expiry_warnings）

#### 不达标项（-30分）

**1. 需求分解过于简单（-12分）**

`rag_flow.py:30-39` 的分解逻辑仅按标点分句：
```python
def decompose_requirement(requirement_text: str) -> list[SubRequirement]:
    parts = [p.strip() for p in re.split(r"[，,；;。]+", requirement_text) if p.strip()]
```

电力工程招标要求通常是复合型长句，如"投标人须具有110kV及以上电压等级变电站施工经验，且近三年累计完成不少于3个类似项目"。简单标点分句会破坏语义完整性，导致"110kV及以上电压等级变电站施工经验"和"近三年累计完成不少于3个类似项目"被拆分后分别检索，丢失关联性。

**2. 子需求分类过于粗糙（-8分）**

仅分为 `MUST` 和 `GENERAL` 两类，无法区分"资质要求""业绩要求""技术参数要求""管理人员要求"等不同维度，影响检索精度。

**3. 缺少电力行业专项重排序（-5分）**

无电力行业术语加权机制。当搜索"110kV变电站施工经验"时，应对包含"变电站""110kV""GIS""主变"等电力术语的证据给予更高相关性分数。

**4. 缺少同类项目优先匹配（-5分）**

电力工程评标时，同类项目（如同电压等级、同类型工程）的业绩权重远高于不同类项目。当前检索无此区分。

### M7 审查引擎模块（达标率：65%）

- [x] 结构化审查报告输出（modeled_issues）

#### 不达标项（-35分）

**1. 审查维度严重不足（-15分）**

电力工程评标专家审查投标文件至少包含以下维度，当前审查引擎主要关注"需求覆盖率"，缺少：

```
缺失的审查维度：
A. 规范引用审查：
   - 引用的电力行业标准是否为现行有效版本
   - DL/T、GB、SD系列标准号是否正确
   - 是否遗漏必引标准

B. 数值一致性审查：
   - 全文中出现的同一参数值是否一致
   - 与GlobalFacts中的数值是否一致
   - 不同章节间的交叉引用是否一致

C. 逻辑完整性审查：
   - 施工方案是否覆盖所有分部分项工程
   - 进度计划的逻辑关系是否合理
   - 资源计划是否与施工方案匹配

D. 评分点响应审查：
   - 评分标准中的每个得分点是否有对应内容
   - 加分项是否已充分展开
   - 创新点/优化方案是否有实质内容

E. 格式合规审查：
   - 是否按招标文件要求的格式组织
   - 表格、图纸是否齐全
   - 签字盖章要求是否满足
```

**2. 缺少跨章节一致性审查（-10分）**

`review_full_document` 将全文拼接后送审，但缺少专项跨章节一致性检查逻辑。例如：施工组织设计中的工期与进度计划中的工期是否一致，技术方案中的设备选型与资源配置计划中的设备清单是否匹配。

**3. 审查结果缺少可操作性（-10分）**

`modeled_issues` 中的 `issue_type` 仅有 `MISSING`/`NON_COMPLIANT`/`LOGICAL_INCONSISTENCY` 三类，缺少修复优先级排序和具体修复建议。评标专家需要的是"第X章第Y节缺少XXX内容，建议补充XXX"这样的精确指引。

## 附录：评审人声明

本评审报告基于对BidExpert系统源代码的实际探查，结合电力工程评标实战经验编制。评审重点关注系统生成的投标文件在电力工程招投标场景下的**合规性**（能否通过形式审查和资格审查）和**竞争力**（能否获得较高评分）。

当前系统技术架构设计合理，RAG+LLM+多门验证的技术路线正确，但**电力行业领域知识深度严重不足**，是导致所有模块均未达到95%达标率的根本原因。建议优先完成P0-致命项整改，使系统具备电力工程投标文件的基本安全保障能力。
