# AI 辅助投标系统

# 企业级技术白皮书 v3.7（质量最大化模型矩阵版）

> 本版本在 v3.6（BYOK +
> 多供应商）基础上，明确"质量最大化优先"的模型推荐矩阵。
> 所有模型仅为"首选建议"，系统必须保持多模型可替换与动态路由能力。

------------------------------------------------------------------------

# 一、总体设计原则

1.  不锁定单一模型厂商
2.  首选模型 ≠ 唯一模型
3.  所有模型通过 Gateway 调用
4.  必须经过：
    -   报价熔断
    -   PII 脱敏
    -   预算控制
    -   审计日志
5.  强制三层防线：
    -   生成
    -   审查
    -   本地 deterministic 校验

------------------------------------------------------------------------

# 三、系统阶段说明

## 1. 入库阶段（历史标书构建专家库）

流程： 1. OCR 2. LangExtract 抽取（Gemini 3 Pro） 3.
Embedding（text-embedding-3-large） 4. Qdrant 入库 5. 元数据写入
PostgreSQL

要求： - 抽取必须 JSON Schema 强校验 - 记录 source_locator - 记录
extraction_method

------------------------------------------------------------------------

## 2. 招标文件处理阶段

1.  文档解析
2.  LangExtract 抽取 Requirement JSON
3.  构建响应矩阵

抽取失败自动 fallback： Gemini → GPT-5 → DeepSeek

------------------------------------------------------------------------

## 3. RAG 检索阶段

-   Hybrid Retrieval（Vector + BM25）
-   Query Rewrite
-   Context Compression
-   必须记录 retrieval_log

------------------------------------------------------------------------

## 4. 章节生成阶段

生成模型默认：Gemini 3 Pro

输出格式： { "content_blocks": \[ {"type": "paragraph", "text": "...",
"evidence_ids": \[\]} \] }

强制： - 不允许生成未绑定证据内容 - 未找到证据必须输出 NEED_HUMAN_INPUT

------------------------------------------------------------------------

## 5. 审查阶段

首选：OpenAI o1

输出 JSON： { "missing_requirements": \[\], "logical_inconsistencies":
\[\], "risk_points": \[\], "coverage_estimate": 0, "score_estimate": 0 }

不得改写正文，只允许输出分析。

------------------------------------------------------------------------

# 四、模型替换机制（必须保留）

1.  所有模型通过 provider_profile 动态配置
2.  新模型通过 Adapter Registry 注册
3.  Model Registry 描述能力与限制
4.  Qualify 测试通过后方可上线
